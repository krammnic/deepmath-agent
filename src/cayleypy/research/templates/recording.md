# Recording research

Use a stable identifier for each hypothesis, experiment, result, review and handoff. Include authorship, date, exact definitions, parameter domain, dependencies with versions, artifact references and the next step. Matching identifiers connect the records for a run.

## Claim and verification statuses

Claim status: open / partial / claimed / proved / refuted / disputed / superseded.

Verification status: not-reviewed / author-checked / independently-reproduced / formally-checked.

A proved status requires a proof of the entire stated claim. Finite cases alone do not suffice. A formally-checked status applies only to the listed statements and assumptions. An independent review records the evidence version, commands, reviewer, expected and observed output, and unchecked portions.

## Reproducibility

Record exact source versions, seed, data, definitions, commands and expected results. Distinguish exact distance from a path upper bound, and finite experiments from universal arguments. Failure to find a certificate within a bounded pool does not refute the mathematical claim.

For formal proofs, preserve the toolchain, dependency manifest, theorem statements and axioms. For benchmarks, preserve the output contract, hardware, GPU count, warmup, repetitions, concurrent load and archived outputs.

## Evidence and changes

Store small verifiable evidence with the run. Large artifacts need immutable storage locations, sizes, SHA-256 checksums, authorship, permissions and verification commands; use the artifact manifest template. Changed artifacts receive new versions. Preserve authorship and links to dependent results when correcting a record.

Review permissions before publication. Keep credentials, private correspondence and unauthorized personal data out of research records.
